---
title: "Why SuperPlane is open source"
description: Learn why SuperPlane keeps the software factory open, inspectable and adaptable.
---

SuperPlane sits between a piece of engineering work and the code that reaches review. It can read an issue, start an agent, run checks and open a pull request. A system with that much responsibility should not be a black box.

That is why the SuperPlane engine is open source under the Apache 2.0 license. You can see how the factory makes decisions, run it in your environment and shape it around the way your team builds software.

<div class="oss-statement">
  <span>The short version</span>
  <strong>Your factory should work for your team. You should be able to see how it works.</strong>
</div>

## Why this matters?

<div class="oss-principles">
  <article>
    <span>01</span>
    <h3>The factory is inspectable</h3>
    <p>Automation can create branches, change code, run tests and request approvals. Open source lets your team inspect that path from the first event to the final result.</p>
  </article>
  <article>
    <span>02</span>
    <h3>You control where work runs</h3>
    <p>Some teams can use managed infrastructure. Others need code, credentials and agent activity to stay inside their own environment. SuperPlane supports both without changing the workflow model.</p>
  </article>
  <article>
    <span>03</span>
    <h3>Your stack stays yours</h3>
    <p>Engineering teams use different repositories, agents, checks and approval rules. An open foundation makes it possible to connect the tools you already trust instead of rebuilding your process around a closed platform.</p>
  </article>
  <article>
    <span>04</span>
    <h3>The project improves in public</h3>
    <p>Issues, fixes and new integrations are easier to evaluate when the work is visible. You can follow a change, test it in context and contribute where your experience can help.</p>
  </article>
</div>

## What is Open?

The public repository contains the engine, web interface, API definitions, integrations, development environment and tests. It is the same foundation used to build SuperPlane.

<div class="oss-facts">
  <div>
    <strong>Apache 2.0</strong>
    <span>A permissive license for using, modifying and distributing the project.</span>
  </div>
  <div>
    <strong>Public development</strong>
    <span>Source, issues, releases and contribution guidelines are available on GitHub.</span>
  </div>
  <div>
    <strong>Flexible operation</strong>
    <span>Run SuperPlane in the cloud or on your own infrastructure and choose the models that fit your work.</span>
  </div>
</div>

## Open source and SuperPlane Cloud

The open source project gives you the factory and the freedom to operate it. SuperPlane Cloud is the managed path for teams that want to use the same foundation without running the supporting infrastructure themselves.

The choice is operational. The workflow stays understandable and the engine stays open.

## Common questions

<div class="oss-faq">
  <details>
    <summary>Can I inspect and change SuperPlane?</summary>
    <p>Yes. The source is public and licensed under Apache 2.0. Review the license before distributing modified versions or using the project in another product.</p>
  </details>
  <details>
    <summary>Can I use my own models and engineering tools?</summary>
    <p>Yes. SuperPlane is designed to coordinate the agents, source control, checks and review systems that make sense for your team.</p>
  </details>
  <details>
    <summary>Do I need to run SuperPlane myself?</summary>
    <p>No. You can operate the open source project on your infrastructure or use SuperPlane Cloud as the managed option.</p>
  </details>
  <details>
    <summary>How can I take part?</summary>
    <p>Read the contribution guide, open a focused issue or join the community to discuss an idea before you build it.</p>
  </details>
</div>
