Report a reproducible product problem through GitHub. Include enough context to identify the failing path without exposing credentials, customer data or private source code.

<div class="bug-report-panel not-content">
  <header>
    <h2>Send a useful bug report</h2>
    <p>A focused report helps the team reproduce the problem and identify the affected workflow.</p>
  </header>

  <div class="bug-report-grid">
    <section>
      <span>01</span>
      <h3>Collect the details</h3>
      <ul>
        <li>SuperPlane version and deployment type</li>
        <li>Browser and operating system</li>
        <li>Workspace area, task state and failed component</li>
        <li>Steps to reproduce the problem</li>
        <li>Expected and actual results</li>
        <li>Relevant error text, timestamps and sanitized logs</li>
      </ul>
    </section>

    <section>
      <span>02</span>
      <h3>Remove sensitive data</h3>
      <p>Remove API keys, session values, tokens, secret fields, repository code, personal data and internal URLs from every attachment.</p>
      <div class="bug-report-note">
        <strong>Before submitting</strong>
        <span>Search existing issues and add information there when the same problem is already tracked.</span>
      </div>
    </section>
  </div>

  <footer>
    <div>
      <span>Ready to share the report?</span>
      <strong>Open a new issue in the SuperPlane repository.</strong>
    </div>
    <a href="https://github.com/superplanehq/superplane/issues/new" target="_blank" rel="noreferrer">Report a bug <span aria-hidden="true">↗</span></a>
  </footer>
</div>
